任务一 ★

事件侦探：一次拖动到底发生了什么

作品：touch-probe.html —— 5 类事件日志（毫秒时间戳+坐标+手指数）、计数格、canvas 轨迹图

验收① 一次拖动里 touchmove 大约触发多少次？

不是一次，而是按帧采样——屏幕一般 60Hz，拖动 1 秒约触发 60 次，距离越远/拖越久触发越多，浏览器不保证每像素都派发。

验收② click 出现在 touchend 之前还是之后？

之后。完整顺序 touchstart → touchmove（若干）→ touchend → （约 300ms 内）→ click，click 是由触摸动作"合成"出来的鼠标事件。

验收③ 把 touchend 换成 touchcancel 会发生什么？

正常松手时 touchcancel 永远不来，程序收不到收尾事件；两者互斥，所以必须都监听——系统来电、手势被浏览器接管时才派发 touchcancel。

坑与解决

  • canvas 轨迹坐标错位：canvas 内部分辨率与 CSS 尺寸不同步，画出的点偏离手指——在 linjie_setupTrail 里按 devicePixelRatio 同步设置内部分辨率。
  • 日志刷屏：touchmove 60Hz 疯狂刷行——限制上限 120 行并按帧合并计数。

任务二 ★★

手势卡片：左右滑动切换内容

作品：mobile-gesture.html —— 4 道菜卡、changedTouches[0] 算横向位移、阈值 40px、边界提示

验收① 距离不够不切换（阈值生效）？

横向位移 |dx| < 40px 直接忽略，只在 touchend 结算一次，避免微小抖动误切。

验收② 快速连滑不会跳两张？

300ms 冷却：切换后写入 linjie_lockUntil 时间戳，冷却期内的新手势整体忽略；再配合"滑出→强制重绘→滑入"两阶段 0.3s 过渡。

验收③ 手机上拖动时页面不会跟着上下滚动？

卡片容器加 touch-action: pan-y——横向手势归 JS，纵向仍允许页面滚动，两不误。

坑与解决

  • 动画第二次不播：两次切换间隔小于动画时长时 class 没变过、动画不重放——"移除类 → void offsetWidth 强制重绘 → 加回类"三连保证每次都播。
  • 边界提示被动画盖住：提示文字用独立节点单独控制显示，不参与卡片过渡。

任务三 ★★★

图片查看器：双指缩放 + 双击放大 + 拖动（加做：双指旋转）

作品：mobile-zoom.html —— 增量缩放 1~4 倍、焦点锚定、边界钳制、双击 1x↔2x、atan2 双指旋转

验收① 缩放以两指中心为基准，图片不会"跳走"？

"缩放不跳"两件套：增量缩放（本次距离/上次距离，每步只乘小比例）+ 焦点锚定公式 tx' = mx − (mx−tx)·(s1/s0)，保证手指下的图像点在缩放前后不动。

验收② 缩放到边界有阻尼或限制？

1~4 倍钳制 + 松手回弹：实时 clampOffset（最大平移 = 尺寸×(scale−1)/2），松手后带 0.25s 过渡吸附回合法边界。

验收③ 1x 时不能拖出边界？

单指拖动仅在 scale>1 生效；scale=1 时最大平移量为 0，天然锁死在居中位。

加做：双指旋转为什么不破坏"缩放不跳"？

Math.atan2 算两指连线角，角度差累加进 rot（±180° 环绕处差值归一化防整圈闪跳）；rotate 写在 scale 之后（CSS 从右往左执行），焦点锚定公式依然精确成立。

坑与解决

  • 2指→1指跳变：双指期间残留位移被继承——touchend 时把拖动基准重置为剩余手指当前位置，角度基准一并清空。
  • 旋转绕左上角甩出屏幕：transform-origin 固定 0 0（缩放公式需要）——在 rotate 前后补 ±中心点的 translate，等价于"绕图片中心转"。

任务四 ★★★★（A 摇一摇 + B 倾斜视差 两个都做）

摇一摇彩蛋 + 倾斜视差

作品：mobile-sensor.html —— devicemotion 阈值 18 抽菜谱（1.5s 冷却）+ 独立五层视差舞台 + 三级降级

验收① 一次摇动只触发一次？

devicemotion 可达 60Hz，一次摇动几十个超阈值事件——触发后写入 1.5s 冷却截止时间戳，冷却期内只更新读数不抽签。

验收② 没有加速度传感器的设备不报错不白屏？

三级分流：DeviceMotionEvent 不存在 → 直接降级；支持但 1 秒内收不到有效数据 → 探测定时器自动降级；降级显示"当前设备不支持，请用手机打开"+"点我抽一次"按钮。

验收③ iOS 通过按钮触发权限申请？

iOS 13+ 要求用户手势触发 requestPermission()——页面先显示"开启体感权限"按钮，授权通过才监听（同一个手势里顺带请求方向传感器权限）。

验收④ accelerationIncludingGravity 与 acceleration 的区别？

前者包含重力分量：手机静止平放时读数约 ±9.8（只有重力），摇动时叠加手部加速度，所以合成模长 √(x²+y²+z²) 静止≈9.8、摇动超 18 可判定；后者剔除重力，静止时接近 0，无法直接判定"有没有摇"。

坑与解决（本关坑最多，3 个真实排错经历）

  • 坑① 手机上摇不了（读数一直 --）：局域网 HTTP 地址不是"安全上下文"，浏览器禁发传感器数据——加"环境诊断"行定位后，改用 openssl 自签证书起 HTTPS 服务器（https-server.js，8443 端口）解决；等价方案还有 chrome://flags 白名单、GitHub Pages 真 HTTPS。
  • 坑② 华为浏览器摇一摇能动、视差不动：它只派发 devicemotion、不派发 deviceorientation——诊断行把"加速度数据/方向数据"拆开显示定位根因，再加兜底：方向数据缺失时用 accelerationIncludingGravity 重力分量（x/9.8, y/9.8）近似倾斜角驱动视差。
  • 坑③ 视差效果太弱看不出：原来只在结果卡片上做 14~30px 位移——单拎成独立五层视差舞台（depth 系数 -12~58，远景反向），幅度加大后一眼可见。
